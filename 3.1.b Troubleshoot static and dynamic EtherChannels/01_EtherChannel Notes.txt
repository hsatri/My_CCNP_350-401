🔴3.1.b Troubleshoot static and dynamic EtherChannels
######################################################

🔴EtherChannels: 
----------------
🔹Link aggregation
🔹make multiple physical interfaces into single logicalinterface
🔹STP will not block multiple links aggregatation.
🔹Invrease BW 
🔹Provides redundancy by aggregating individual links of switch.
🔹Load-balnces traffic over all links
🔹its  can be configured as L2/L3.
🔹max ether-channel to 8 physical interfaces.

🔴EtherChannel protocols: 
-------------------------
🔹PAgP(Port Aggregation Protocol):
	- CISCO proprietary
	- MAC @ : 0100:0CCC:CCCC 

🔹LACP(Link Aggregation Protocol):
	- Standard.
	- MAC @ : 0180:C200:0002

🔹Manual/Static Mode without protocol.


🔴EtherChannel Requirements : 
-----------------------------
🔹Duplex : should be the same
🔹Speed
🔹Same Native and allowed vlans.
🔹same switchport mode (access/trunk).


📌Options we can chose for interface:
	➤ ON : int becomes member of the ETHCHANNEL but does not negotiate.
	➤ Desirable : int will actively ask the other side to become an ethchannel
	➤ Auto : int wait passibely for other side to ask to become an ether-channel.
	➤ OFF : no eth-channel configured on the interface.

🔴 Modes : 
-----------
🔹LACP (Link Aggregation Control Protocol) :
	🔹Modes:
		➤ Active  : Sends LACP packets to initiate negotiation.
		➤ Passive : Waits for LACP packets to respond.
+---------------------------------------------+
| Local Mode | Remote Mode  | Channel Formed? |
|------------|--------------|-----------------|
| Active     | Active       | Yes             |
| Active     | Passive      | Yes             |
| Passive    | Active       | Yes             |
| Passive    | Passive      | No              |


🔹PAgP (port Aggregation Protocol):
	🔹Modes:
		➤ Desirable: Actively sends PAgP packets to negotiate.
		➤ Auto     : Listens/responds but doesn’t initiate.
+---------------------------------------------+
| Local Mode | Remote Mode  | Channel Formed? |
|------------|--------------|-----------------|
| Desirable  | Desirable    | Yes             |
| Desirable  | Auto         | Yes             |
| Auto       | Desirable    | Yes             |
| Auto       | Auto         | No              |


🔹EtherChannel static(Manual):
	➤ switchportcan be configured to bypass LACP or PAgP Protocols.
	➤ simply changingthe mode to 'ON' both sides of the switches.
	➤ to configure etherchannel manually.

🔴 To Check Etherchannel : 
--------------------------
	#sh spanning-tree vlan 1
	#sh etherchannel summary
	#sh etherchannel detail
	#sh etherchannel port-channel


🔴Etherchannel Troubleshoot: 
----------------------------
🔹Most of the issues with Etherchannels are the cause of misconfiguration.
🔹configuration of all physical interfaces has to match.
🔹due to logical all the member interfaces must have the same characteristics.

📌 Port Type:
	➤ Every port in interface must be consistently configured to be L2/L3.
	➤ 

📌 Prt Mode:
	➤ All L2 port channels must be :
		- configured as either access port or trunk ports.
		- same configuration ports cannot be mixed.

📌Native VLAN:
	➤ Member interfaces on L2 Port channels must be configured same native VLAN.
	➤ Conf of native VLAN: switchport trunk native vlan (vlan-id)

📌Allowed VLAN:
	➤ Member interfaces on L2 ; trunk poert channel must be configured same VLANs.
	➤ Same allow VLAN can be configured using command "switchport trunk allowed 'vlan-id'"
	
📌speed :
	➤ All member interfaces or ports in port channel must be the same speed.
	➤ CLI#show int status


📌Duplex ; 
	➤ the duplex must be the same for all member interface or ports in port channel link.
	➤ 
		CLI#int fe0/0
		CLI#duplex [auto | full | half]
📌MTU:
	➤ All L3 member interfaces or ports must have the same MTU configured
	➤ CLI#show int fa0/0
